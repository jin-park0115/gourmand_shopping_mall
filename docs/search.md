## 검색 규칙 (`SearchQuery`, 순수 파이썬)

FastAPI · SQLAlchemy를 모르는 도메인 클래스예요. 검색어를 한 번 풀어 두고 상품 글자와 비교해요.

1. **띄어쓰기 · 대소문자 무시**: "도쿄 바나나" = "도쿄바나나", "POCKY" = "pocky"
2. **자모 비교**: 한글 한 글자를 초성 · 중성 · 종성으로 풀어요.
   - 유니코드 "가"(`0xAC00`)부터의 거리 `i` 로 계산: 초성 `i // 588`, 중성 `(i % 588) // 28`, 종성 `i % 28`
   - "초코" → `ㅊㅗㅋㅗ`, "초콜릿" → `ㅊㅗㅋㅗㄹㄹㅣㅅ` → 앞이 같아서 찾음
   - 치는 중인 "곤야"(`ㄱㅗㄴㅇㅑ`)도 "곤약"(`ㄱㅗㄴㅇㅑㄱ`) 안에 있어서 찾음
   - 겹모음 · 겹받침은 펼쳐서 같게: "ㅘ" = "ㅗㅏ", "ㄺ" = "ㄹㄱ"
3. **초성 검색**: 검색어가 자음만이면 **상품명의 초성하고만** 비교해요. "ㄱㅇㅈㄹ" → 곤약젤리
   - 자모로 비교하면 받침 ㄱ + 다음 글자 ㅇ처럼 글자 경계를 넘어 엉뚱하게 걸려서 따로 처리해요
4. **동의어**: 자주 다르게 치는 말을 상품 정보에 쓰인 말로 바꾼 검색어도 함께 찾아요

   | 이렇게 쳐도 | 이걸로 찾아요 |
   |---|---|
   | 초콜렛 · 쵸콜릿 · 쵸콜렛 | 초콜릿 |
   | 쵸코 | 초코 |
   | 비스켓 | 비스킷 |
   | 구미 | 젤리 |

## 요청이 처리되는 길

```
검색창 (SearchField.tsx) ─ 0.2초 멈추면 ─▶ GET /products/suggest   (자동완성)
검색 화면 (/search)      ────────────────▶ GET /products?q=…      (결과 목록)
        │
presentation  router.py      q 최대 50자 · page/size 범위 검증 (어기면 422)
application   service.py     검색 · 필터 · 정렬 · 페이지 요청을 Repository 로
infrastructure repositories  상품 글자를 읽어 SearchQuery 로 맞는 번호를 고르고,
                             나라 · 카테고리 필터 · 정렬 · 페이지는 SQL 로
domain        search.py      자모 · 초성 · 동의어 비교 (위 규칙)
```

- 찾는 범위: 상품명 · 나라 · 카테고리 · 제조사 · 식품유형 · 설명
- 추천순이면 **상품명에서 찾은 상품이 먼저**, 그다음 평점 순
- 정렬 5가지: 추천 · 리뷰 많은 · 낮은 가격 · 높은 가격 · 신상품
- 품절은 항상 맨 뒤, 같은 순위면 상품 번호 순 (페이지를 넘겨도 순서가 흔들리지 않아요)

## 자동완성

- `GET /products/suggest?q=…`: 이름이 맞는 **카테고리 · 나라**, 추천순 **상품 5개**, **전체 개수**를 한 번에 돌려줘요
- 프론트는 입력이 **0.2초 멈추면** 요청하고, 더 치면 이전 요청을 `AbortController`로 취소해요 (늦게 온 옛 결과가 새 결과를 덮지 않게)
- 키보드 ↑ ↓ · Enter, 화면 읽기 프로그램용 `combobox` · `listbox` 역할
- 실패하면 조용히 숨겨요 (보조 기능이라 검색 자체는 그대로 돼요)
